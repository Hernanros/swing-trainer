<decisions_made>

**UI decisions (confirmed by user):**
- Layout: Option B — ranked table + expandable rows (not cards, not brief)
- KPI placement: Option C — mini 4-number strip on Bull page (collapsed by default) + full Bull Performance section on Progress page (also collapsed by default)
- User explicitly said: "I don't want the dashboard distracting me at all times"

**Algorithm decisions:**
- Channel detection: linear regression on 20-day highs/lows; stock must be in bottom 25% of channel (proximity_pct ≤ 0.25) with positive channel slope
- RSI slope (direction) matters more than RSI value; 3-bar slope must be positive
- Deterministic score 0-100 replaces Claude Haiku batch scoring entirely
- Claude Sonnet writes 2-3 sentence qualitative brief only (not a scorer)

**Data decisions:**
- S&P 500 (~450) for technical stage (yfinance batch — reliable)
- Top 20 technical survivors → per-ticker options check (yfinance, more reliable than batch)
- OptionsProvider abstraction: YFinanceOptionsProvider POC now, TradierOptionsProvider stub ready (one env var to activate)
- User has TradingView (no API) + OptionStrat free (no API) + IBKR Israel (complex auth, future)
- User willing to pay ~$10-20/month for data after POC value demonstrated

**Screener setup criteria (from user):**
- Macro: bullish market OR credible reversal signal (sector rotation, news, RSI from oversold)
- Chart: upward channel, stock floating near BOTTOM of channel (support test)
- RSI: turning upward (slope positive)
- Volume: confirming (≥ 80% of 20d avg)
- Options style: ATM or ITM short put, 5-7 DTE weekly, aggressive credit, capitalize in first week

**Paper trade decisions:**
- Auto-log all complete candidates (score ≥ 60) on every scan — no user action required
- Auto-resolve on expiry via APScheduler at 4:30 PM ET
- Sprint 2 ML triggers after 50+ resolved paper trades

## Critical Anti-Patterns (do NOT repeat)
- **DO NOT use yfinance batch for options data** — it is unreliable for IV/OI. Use `YFinanceOptionsProvider` per-ticker for options stage only.
- **DO NOT pass null IV/OI to Claude** — assign `data_quality` flag instead, skip brief for non-complete candidates
- **DO NOT let Claude score candidates** — deterministic scoring only; Claude writes qualitative brief only
- **DO NOT exceed 20 candidates in the options stage** — per-ticker calls are slow; only run on top 20 technical survivors
